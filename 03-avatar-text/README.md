# 头像文字贴纸

选一张图，打一行字，直接存成能用的头像。纯本地运行，不联网、不登录、图片不上传。

系列第三个工具，一天一个。

## 功能

- **选图**：从相册选一张，或者用内置示例图先试效果
- **文字**：最多 12 字，一个字也能撑住画面
- **字体**：粗黑、宋体、细黑、等宽，四种
- **颜色**：六个预设色 + 「自动」——按图片平均亮度挑对比度最高的黑或白
- **位置**：上 / 中 / 下三档，默认下面（不挡脸）
- **描边**：默认开，线宽随字号走，白字配黑边
- **字号自适应**：6 字以内一行，超过自动均分两行；缩到下限还放不下就提示「字有点多」
- **导出**：跟原图同尺寸，最长边超过 1600 等比压到 1600
- 免费 2 次，激励视频解锁后不限次

2. AppID 选「测试号」即可（`project.config.json` 里是 `touristappid`）
3. 编译，直接可用

**逻辑自测**

```bash

```

**浏览器预览**

## 核心设计：只算计划，不画像素

`core/sticker.js` 不碰 canvas。它输出一份**绘制计划**：

```js
{
  canvas: { w, h },
  text: {
    lines: [ { chars: [{ ch, x, y, w }], width, x, y } ],
    size, lineHeight, color, strokeWidth, strokeColor, cssFont,
    font: { id, name, family, weight }
  },
  box: { x, y, w, h },
  bgLayers: [...]     // 示例头像的图层描述
}
```

小程序 canvas 和浏览器 canvas 各自照着这份计划画。好处有两个：

1. 两处排版一定一致，不会出现「视频里的界面」和「真机界面」不一样
2. 排版能在 node 里测——字号、断行、边界这些最容易错的，都在测试里

字宽用 `charEm()` 估算（中文 1em，西文按字号比例），不调 `measureText`。因为 node 里没有 canvas，测不了真实字宽。估算的误差由 8% 的安全边距吸收，测试里断言「每个字的右边界不出安全区」。

## 排版规则

| 情况 | 处理 |
|---|---|
| 1–6 字 | 一行，字号取 `min(画布高×0.30, 画布宽×0.42, 安全宽/字宽)` |
| 7–12 字 | 均分两行，切点取「两行字符数最接近」的那个 |
| 仍放不下 | 每次缩 2px，到下限（画布高×3.5%）停 |
| 缩到下限还溢出 | 给「字有点多」提示，不硬截断 |

## 广告位

`core/ads.js` 顶部有一个常量：

```js
var AD_UNIT_ID = '';   // 拿到流量主后填这里
```

**现在是空的，这是有意的**。新小程序没有流量主权限（需累计独立访客 ≥1000），此时填任何 ID 都会触发「广告拉取失败」。所以代码做了降级：拉不到广告 → 视为解锁成功，直接放行。

拿到流量主后，把真实 `adUnitId` 填进这个常量，其余代码不用动。

## 页面结构

单一页面 `pages/index`：

| 区块 | 说明 |
|---|---|
| 画布 | 按图片比例自适应显示，最高 380px |
| 选图 | 相册选图 / 示例图，选完立刻预览 |
| 文字 | input，12 字上限 |
| 字体 / 颜色 / 位置 | 三组 chip 与色板 |
| 描边 | switch，默认开 |
| 主按钮 | 无结果时「生成头像」，有结果时「重新生成」 |
| 结果 | 尺寸 + 字体 + 行数 + 存到相册 |
| 解锁 | 免费 2 次之外的部分 |

## 已知限制

- 字体用的是系统字体族（sans-serif / serif / monospace），不是打包字体。不同机型上同一个「宋体」可能略有差别
- 文字只支持单行居中排版，不能拖拽到任意位置、不能旋转
- 不做抠图、不做人脸避让——「下」档只是把字放在画布 78% 的高度，不代表一定避开人脸
- 一次只处理一张图，没有批量
- 保存走系统相册权限，用户拒绝后只能引导去设置

## 设计取舍

**为什么把排版抽到 core 而不是在页面里算**：字号自适应是有取舍的（一行放不下就缩、缩到下限就断行），页面和小程序各写一遍必然长得不一样，视频里的界面就会骗人。抽到 core 后，两边共用一份，测试也只测一份。

**为什么示例头像是坐标描述而不是一张图**：预览页和小程序包里各放一张图，改一次要改两处，还增加包体积。用图层坐标描述，两边画出来完全一致，代价是只能画几何形状。

**为什么「自动」颜色要采样图片亮度**：白字压在浅色照片上就是看不见。采样后取对比度更高的黑或白，比让用户自己踩这个坑省事。采样只在选图/生成时做一次，1600 长的图取 40×40 个点，开销可以忽略。

**为什么导出要限 1600**：`canvasToTempFilePath` 出来的图直接进相册，4000px 的原图既慢又没必要——头像显示尺寸最多 500px。
