# 转盘抽签

选项一行一个填进去，点一下转，停下来那格就是答案。纯本地算，不联网、不登录。

系列第八个工具，一天一个。

## 功能

- **选项随手填**：一行一个，中英文逗号、顿号、分号、制表符都当分隔符；行首的「1.」「-」「·」自动去掉；重复项按小写比对后只留一个；空行忽略
- **2–12 个选项**：少于两个转不起来，多于十二个扇区就糊了，两头都拦下并给出可直接弹的提示
- **真转不是假转**：扇区按选项数等分，命中哪一格由「落点角度」反算，转完再回读一次校验（`landed`）
- **不放回**：抽过的标签不再进池，一轮抽完自动开新一轮，轮次写进记录
- **四套现成选项**：吃什么 / 谁买单 / 今天做啥 / 周末去哪，点一下整组填进去
- **记录**：免费存 5 条，解锁后 60 条；按标签统计次数，谁中得多一眼看到；可复制整份记录
- **配色固定**：六个低饱和色循环使用，相邻（含首尾）不同色，字色按底色亮度自动取黑或白

## 核心设计

### 角度：两个函数互为逆运算

全部角度都用「从 12 点方向起、顺时针为正」这一套，避免渲染层自己再做一次换算。

- 第 `i` 格占 `[i*seg, (i+1)*seg)`，`seg = 360/n`
- 指针固定在 0°。第 `i` 格的中心 `c_i = (i+0.5)*seg`，当 `c_i + rotation ≡ 0 (mod 360)` 时它正好压在指针下
- 所以命中 `i` 需要的最终角 `F_i = (360 - c_i) mod 360`，再补 `turns` 整圈保证「转得比现在多」
- `indexAt(rotation)` 走反向：`ang = (360 - rotation) mod 360`，`i = floor(ang / seg)`

这两个函数在测试里互相验证：对 2–12 格、每个格子、任意起始角（0–720 步长 37）
都要求 `indexAt(targetRotation(i)) === i`，一条不成立就退出码 1。

### 为什么先按行切、再去序号

顿号既是分隔符，又常被当成序号后缀（`3、日料`）。如果先把顿号换成换行，
序号就落到下一行，变成一个孤零零的「3」，混进选项里。
所以顺序是：按行切 → 去行首 `- * · • 1. 1、 1)` → 再按 `, ， 、 ; ； \t` 切行内。
`12点睡` 这种不会被误伤，因为序号后面必须跟标点。

### 扇区颜色：相邻不同色

六个颜色循环取，只有在 `n % 6 === 1` 时末项会和首项撞色（7 格：0–5 用完回到 0），
这时把末项往后挪一格。测试对 2–12 格逐格检查「相邻（含首尾）颜色都不同」。

字色不用手挑：按底色亮度 `0.299R + 0.587G + 0.114B` 算，超过 0.70 写深色字，否则写白字。
黄底写白字会糊成一片，这条规则两个渲染层共用。

### 标签翻转

标签挂在「圆心 → 12 点」的竖条上，整条转 `mid` 度就落到对应扇区。
`mid` 落在下半圈（90°–270°）时字是倒的，所以标记 `flip`，渲染层给文字再套一个 `rotate(180deg)`。
旋转是绕文字自身中心做的，位置不变，只是方向摆正。

### 失败返回对象，不抛异常

`{ ok:false, code, message }`，页面把 `message` 直接弹 toast。code 给测试和分支用：
`TOO_FEW` / `TOO_MANY` / `TOO_LONG`。

## 广告位

`core/ads.js` 顶部有一个常量：

```js
var AD_UNIT_ID = '';   // 拿到流量主后填这里
```

**现在是空的，这是有意的**。新小程序没有流量主权限（需累计独立访客 ≥1000），此时填任何 ID
都会触发「广告拉取失败」。所以代码做了降级：拉不到广告 → 视为解锁成功，直接放行。

## 已知限制

- 只做等概率抽签，不支持给选项配权重
- 「不放回」的去重按标签文本，两个同名选项会被当成同一项（解析阶段就会去重）
- 转盘用 `conic-gradient` 画底色，基础库过低的环境会退化成一圈灰底（标签仍在）
- 记录存本地 Storage，换设备不同步
- 选项上限 12 个是刻意的：再多扇区里的标签就挤成一条线了
