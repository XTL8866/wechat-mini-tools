# 祝福语生成

写上名字、选好场合和口气，直接出能发的祝福语。纯本地运行，不联网、不登录。

系列第四个工具，一天一个。

## 功能

- **四个场合**：生日 / 中秋 / 拜年 / 开业
- **三种口气**：温暖（熟人）、得体（长辈客户）、俏皮（朋友）
- **60 条模板**：4 场景 × 3 语气 × 5 条，名字替换后句子读得通
- **字数与短信条数**：超过 70 字标「2 条短信」，发之前就知道会不会被拆
- **去重**：同一个人连续点「换一批」，不会拿到刚看过的句子；池子用尽才允许重复并提示
- **补齐提示**：某个语气的说法用完了，会混入其他语气并说明，标签跟着模板走
- 免费 3 条，激励视频解锁后一次 15 条

## 核心设计：场景和语气是两个维度

`core/wishes.js` 的模板按 `场景 → 语气 → 5 条` 三层存：

```js
TEMPLATES.birthday.formal[0]
// { id: 'bd-f1', text: '{n}，谨祝生日快乐。愿事业顺遂，身体康健，诸事如意。',
//   tone: 'formal', scene: 'birthday' }
```

场景决定「说什么事」（过生日 / 团圆 / 过年 / 开张），语气决定「拿什么调子说」。两层正交，4 × 3 = 12 个格子，每格 5 条，改文案只要往对应格子里加。

**为什么不用一个大池子加标签过滤**：祝福语的语义和场景强绑定，「开业大吉」放到生日场景就是错的。按格子存，生成时只会跨语气补，绝不会跨场景串台——这一条在测试里断言了。

**为什么语气标签要跟着模板走**：某个语气只有 5 条，凑 15 条时必然要混入别的语气。如果标签跟着「用户选的语气」走，用户会看到一句正式口吻的祝福被标成「温暖」。所以模板初始化时把 `tone` 写回自身，出结果时读模板的 `tone`。

## 短信拆条

`SMS_UNIT = 70`，`smsParts()` 按 `ceil(字数 / 70)` 算。这是运营商的经典口径，一条短信 70 字（含标点），超了会拆成两条计费。工具里只做提示，不截断——祝福语截断会变成病句。

## 广告位

`core/ads.js` 顶部有一个常量：

```js
var AD_UNIT_ID = '';   // 拿到流量主后填这里
```

**现在是空的，这是有意的**。新小程序没有流量主权限（需累计独立访客 ≥1000），此时填任何 ID 都会触发「广告拉取失败」。所以代码做了降级：拉不到广告 → 视为解锁成功，直接放行。

## 已知限制

- 模板是本地固定的 60 条，不会「学习」用户口吻，也不会根据关系远近自动挑语气
- 不支持自定义场合（比如升职、搬家），加场景要改代码
- 名字只做首尾去标点、空格折叠，不判断是不是真的名字
- 没有历史记录，关掉就没了；复制走剪贴板，不落盘
